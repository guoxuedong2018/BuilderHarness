# 功能宣贯物料

## 这个仓库比「开个网页录屏」多了什么

物料生产要把它们全用上；只当成一个能截图的网页，就浪费了这套 harness。

| 手里有的 | 在物料里变成 | 怎么用 |
|---|---|---|
| **活的原型 + 虚拟时钟** | 产品代码照常运行：点了按钮，抽屉用它自己的过渡滑出，提示按它自己的延时出现。时间按帧拨，每帧确定、可重渲，帧率分辨率随便定，推近多少倍字都是矢量 | 场景时间轴里写 `click` / `hover` / `drop`…（`promo/stage.js`） |
| **需求件套** | 一个需求有哪些场景、每个场景从什么状态开始、每句话的出处 | 场景清单按 FRS 的 `spec` 分组、`FLOW.md` 主流程定；开场状态写 `from: "<截图配方>"`，直接用 `FRS.json` 的 `shots`；`kb context <路由>` 取规格原文（带草案 / 已确认） |
| **源码与源码坐标** | 镜头、标注锚在**元素**上，不是像素上；页面改了重渲一次就跟上 | 读宿主页面源码找锚点；选择器同截图录屏一套：`text=`、`field=`、CSS、`[data-comp=…]` |
| **活的 DOM** | 原型装进一个能做 3D 机位的窗口；要读的组件从页面里**抽离**出来（其余部分按时间淡掉，组件照常能输入、会变）；整屏**字卡**逐字入场 | 时间轴里写 `camera` 带 `tilt`、`isolate`、`title`（`stage.js` 文件头） |
| **CDP** | 渲染时点击、悬停、输入走 Input 域：光标画在哪浏览器就在哪命中，`:hover` / `:active` / 焦点都是真的，被挡住会报；几个浏览器并行渲场景 | 渲染器自动接上；`--synthetic` 退回合成事件，`--jobs` 定并行数 |
| **状态注入与合成数据** | 页面要什么状态就摆什么状态；数据按剧情造（上传用的 Excel 可以用原型自己的写表函数现做） | `state`、`prepare`、mock 数据、`builderharness fixtures generate` 或宿主生成的演示素材 |
| **导航登记** | 配文里的「在哪用」和导航上的字一模一样 | 宿主的导航配置 + 页面源码里的按钮、页签名 |
| **设计 tokens** | 标注用的就是产品此刻的配色 | 舞台自动把原型的 `--color-*` 搬过来 |
| **路由 → 源码依赖** | 源码改了，知道哪份物料过期了 | 渲染时记指纹；`builderharness promo status` 报该重渲的 |

做法综合自两个公开仓库：[video-shotcraft](https://github.com/Vincentwei1021/video-shotcraft)（真实界面 + 运镜、判例式审美准则、交付前独立终检）
与 [mg-styles-15](https://github.com/Vincentwei1021/mg-styles-15)（页面画任意时刻、逐帧截、另开 AI 当评委改一轮）。
它们拿到的只有网页或截图，这里拿到的是源码、需求件套与运行中的产品。

## 读者是谁，他要知道什么

读者是在用（或该用）这个工具的人，在群聊里刷到一张动图，停留两三秒。三件事要讲清：

1. **多了什么 / 变了什么**：用界面上的原名说，不起宣传名。
2. **对我有什么用**：一句话，说他少做了哪一步、能看见什么以前看不见的。
3. **在哪儿用**：入口路径，和导航上的字一模一样。

**画面里说话的只有三样：字卡、窗口标题栏、贴在元素旁的标注。** 字卡整屏、一句价值，放在开头（也是首帧）和转折处；
标题栏写入口路径（和导航上的字一模一样）；标注一个镜头最多一条，只补画面上没有的话。不给画面套固定版式、不加文案栏——
固定的左右栏会重复同一构图。按功能价值选镜头，例如字卡开场、进入产品窗口、抽离关键组件、展示操作结果。

和品牌片（参考仓库）几处反着取：

| 品牌片 | 工具宣贯 | 为什么 |
|---|---|---|
| 配乐、音效卡点 | **默认无声**；MP4 可选配乐 | 群聊里动图静音自动循环，意思要由画面和标注讲清 |
| 开场钩子 → 高潮 → 收尾 | **首帧单独看得懂**（一句价值的字卡，或主角画面），首尾接成一圈 | 没点开之前只看得到第一帧；循环播放没有片头 |
| 风格越鲜明越好 | **长成产品自己的样子** | 读者要认出这就是他天天用的那个页面 |
| 一支片讲一个故事 | **一个场景一张图，一个需求一组** | 一张图讲两件事，两件都记不住；一个需求不只一个动作 |
| 可以虚构品牌与文案 | **每句话都有出处** | 宣贯说错一个入口，比不发还糟 |

## 两种片型：先选对，再动手

| 片型 | 目的 | 时长 | 主角 | 默认声音 |
|---|---|---|---|---|
| **功能宣贯** | 让已用产品的人知道“多了什么、怎么用” | 每个场景 8–12 秒，3–5 个场景 | 真实页面 + 标注 | 无声；MP4 可选配乐 |
| **产品价值片** | 让潜在用户/客户在 3 秒内记住“为什么值得” | 15 / 30 / 45 秒 | 真实产品 + 文字 + 简单品牌动效 | 先无声，后续接 TTS/音乐 |

功能宣贯是“讲清楚一个更新”，产品价值片是“讲清楚一个产品为什么值得”。同一支片不要同时承担两件事。

## 产品价值片：30 秒默认结构

| 时间 | 节拍 | 任务 | 画面 |
|---|---|---|---|
| 0–3s | Hook | 让人停下来 | 结果画面、前后对比、产品高光特写 |
| 3–8s | Value | 说清对谁有什么用 | 产品全景 + 一句价值字幕 |
| 8–18s | Proof | 证明不是概念 | 2–3 个真实操作，每个 3–5 秒 |
| 18–24s | Detail | 展示精致与可信 | 微交互、数据、引用、权限、导出 |
| 24–30s | Close | 记住品牌 | 产品名 + 一句话 + CTA，停 ≥2 秒 |

15 秒只留 Hook、Value、一个 Proof、Close；45 秒在 Proof 后加“输入 → 处理 → 可检查结果 → 人的确认”机制段。

**没有真人、没有口播时，画面必须自己讲清楚三件事：**

1. 这是什么产品；
2. 它替用户完成了什么结果；
3. 为什么这个结果可信。

产品价值片的完整方法、视觉系统、七种 Hook、失败案例与自检清单见 [references/product-film.md](references/product-film.md)。简单品牌动效（渐变球、动态字卡、指标数字、卡片堆叠、Logo 墙、擦除对比、聚光灯、结尾卡）的 CSS/JS 配方见 [references/motion-recipes.md](references/motion-recipes.md)。品牌资产、开源字体和声音设计见 [references/brand-assets.md](references/brand-assets.md)、[references/sound-design.md](references/sound-design.md)；外部工具选型见 [references/toolchain.md](references/toolchain.md)。

## 产品价值片的动效预算

一支 30 秒片最多用：

- 1 个 Hook 动效（字卡或结果画面）
- 2 个镜头运动（推近 + 平移）
- 1 个品牌符号（渐变球 / Logo 墙 / 产品色块）
- 1 个证据动效（数字 / 擦除 / 聚光）
- 1 个结尾卡

超过这个数量，就会从“高级”变成“特效展示”。所有动效写成 `t` 的纯函数；不要用 `Math.random()`、`Date.now()` 或 CSS transition 驱动画面状态。

## 流程：以需求为单位，便宜的确认放前面

### 1. 列场景（不写代码）

读需求件套，列出重要使用场景，在回复里给一张表（用户说「你定」就自己定）：

- 来源：FRS `spec` 的页面分组、`FLOW.md` 的主流程、`shots`（PRD 截图配方，每条就是一个 PM 确认过的关键状态）；
- 每个场景一行：讲什么（读者用户的话）、规格出处（FP 编号）、开场状态（哪条截图配方，或自己写 `prepare`）；
- 一般 3–5 个。挑「用户会自己去做的事」，不挑「系统在背后做的事」；样式微调、文案改名并进别的场景或只写进配文；
- **状态是草案的不写成已上线**，样张、预告要标出来；
- **每个场景到线上走一遍**（只看、不提交）：原型 = 线上 + 还没上线的 Delta，照原型拍会把没上线的东西拍进去。差异记下来，第 3 步对齐。

角度怎么挑、标注和配文怎么写，见 [references/angles.md](references/angles.md)。

### 2. 分镜

每个场景从 [references/shots.md](references/shots.md) 选一个骨架（默认 E：字卡 → 窗口升起 → 真操作 → 抽离特写 → 退场接回字卡），
按秒写节拍：镜头对准什么、对原型做什么、哪条标注出现、停多久。
一个镜头只讲一个动作；关键信息落定后停 ≥1.2 秒；一个场景 10–15 秒。能让真组件自己反馈的，就让它反馈，不手画仿真。

### 3. 写 scenes.js

`docs/promo/<需求 KEY>/scenes.js`，默认导出 `{ frs, viewport?, scenes: [...] }`；时间轴条目的写法见 `promo/stage.js` 文件头。
dev 服务给这个目录一张通用舞台页，不用写 HTML。范例：`docs/promo/09202047_EVAL_SET_LOCAL_IMPORT/scenes.js`（四个场景）。要点：

- 首帧单独看得懂：开场字卡（`title`，`at: 0` 时首帧就是写好的整句；`kicker` 写入口路径——窗口标题栏在 GIF 里太小，读不出），
  或用 `from` / `prepare` 把页面摆到主角状态；字卡说过的话，标注不再说；
- 窗口：`frame: "window"` + `tilt` + `where`（标题栏写入口路径）建立「在哪儿」；**要读的时候正视**——推近的镜头写 `tilt: [0, 0]`，
  组件说明用 `isolate`（自带正视推近）；
- 真操作：`click` / `hover` / `type`（逐字输入，`append` 接着原内容打）由 CDP 真鼠标、真键盘做，渲染日志里的「被 … 挡住，改用合成点击」要处理；
- 原型按 `viewport` 排版（默认同画布 1280×720；抽屉、宽表格多的页面给 1600×900 或 1920×1080），全景时整页缩进画面，推近再放大；
- 时间轴里不安排要等网络的动作；读文件、解压这类异步工作用 `then: 选择器` 等它做完；
- 白场 `dip` 里换状态（换回空的上传区）；`pointer: false` 的动作不画光标；
- 片头、片尾：没有 `route` 的场景就是纯字卡，`only: "film"` 只进总片；每个场景写 `film: [起, 止]`，总片里砍掉收尾那张循环用的字卡；
- 只停一两秒的真反馈（成功提示）用 `hold` 定格读清，不去改产品的时长；顶层 `css` 每个场景都加（如藏掉导航栏的「原型」标记）；
- 海报（`poster`）挑没有光标的时刻：标注已出、光标收起；
- 对齐线上：原型多出来的用场景的 `css` 藏掉，少的在 `prepare` 里补，数字取自真实状态（范例 pick 场景）。这些差异写在 `scenes.js` 顶部。

预览：内置浏览器打开 `http://localhost:5173/__promo/<需求 KEY>/`，各场景依次实时播放；`?scene=<id>&t=3.2` 停在那一帧。
预览没有 CDP 通道，动作走合成事件：按钮的悬停色这类只在渲染出来的成片里有。
准则见 [references/craft.md](references/craft.md)。

### 4. 先静帧，再整片

```bash
builderharness promo render docs/promo/<KEY> --only stills --scene <id> --stills 0.5,3,5.5,8
builderharness promo render docs/promo/<KEY>            # 全部场景 + 总片
```

渲染前会先空跑一遍时间轴，选择器找不到、元素不在页面上时直接报「第 N 秒找不到 «…»」。静帧拼成一张看：
构图、字号、标注位置、真组件的状态对不对；每一张静帧都要像一张能单独发的图。

### 5. 自检与独立评审

看每个场景的 `<id>.contact.png`（每 0.5 秒一格）与 GIF 本身，按 craft.md 末尾的清单过一遍。交付前按独立审片清单复核；
在宿主支持且任务已授权独立评审时，只给评审者成片、联系表、场景表与 [references/review.md](references/review.md)。按评审改一轮再交；首检不交给用户。

## 产品价值片流程

### 1. 写一句话价值

```text
[谁] 可以 [完成什么结果]，不用 [原来的代价]。
```

写不出来就先别做动效。一个价值片只讲一句话；功能点最多作为证据，不做并列卖点。

### 2. 选时长和节拍

15 秒：Hook → Value → 一个 Proof → Close。
30 秒：Hook → Value → 2–3 个 Proof → Detail → Close。
45 秒：30 秒结构 + 机制段（输入 → 处理 → 可检查结果 → 人的确认）。

每个 beat 写：时间、画面、产品路由、动作、字幕、声音点。不要先写“炫酷转场”，先写读者要记住什么。

### 3. 先做 5 张静帧

首帧（Hook）、价值帧、证据帧、细节帧、结尾帧。每张单独看都要像一张能发布的海报；首帧缩到 480 宽仍能读出产品是什么。

### 4. 再写 scenes.js / 自定义画面页

- 每 4–6 秒换一次构图，不要只在一个页面上推拉；暗场标题、产品窗口、细节特写、浅色证据页、品牌结尾轮换。
- 尽量切 2–3 个真实路由/状态（如 Overview / Review queue / Experiments），不要所有镜头都来自同一页。
- 品牌资产放 `brand.json`：名称、价值句、Logo、主色、字体；字体用 Inter + Noto Sans SC（OFL）。
- 以真实页面为主：`route`、`camera`、`click`、`hover`、`note`；
- 品牌动效作为叠层：用 [motion-recipes.md](references/motion-recipes.md) 的 CSS/SVG，写成 `t` 的纯函数；
- 不要给每个功能都做一个镜头；30 秒最多 3 个证据；
- 声音先留注释：`// VO:`、`// SFX:`、`// MUSIC:`，暂不生成音轨。

### 5. 渲染与评审

先 `--only stills` 看 5 张静帧；再渲染单场景；最后拼总片。按 [references/review.md](references/review.md) 的“产品价值片”评分表做一次独立评审，重点看首 3 秒、价值清晰度、产品真实感和动效克制。

### 6. 五项硬要求

- **多页面**：至少 2–3 个真实路由/状态，不要所有镜头都来自同一页。
- **品牌资产**：`brand.json` 管名称、价值句、Logo、主色、字体；Logo 用 SVG。
- **设计化裁切**：至少 2 个细节镜头，聚焦具体元素，并用标签/边缘柔化避免“半截文字”。
- **声音**：无旁白也要有低频氛围 + 转场/点击音效；保留无音轨母版。
- **字体**：Inter + Noto Sans SC（OFL），统一字阶、字距、数字对齐。

## 交付

| 产物 | 用途 | 默认规格 |
|---|---|---|
| `out/<场景>.gif` | 群聊里主力，一个场景一张，自动循环 | 960 宽、15fps、≤5MB（超了自动先降质量再缩宽） |
| `out/<场景>.png` | 海报：动图发不了的地方、文档封面 | 1920×1080，取 `poster` 时刻（默认 0.8 秒） |
| `out/<场景>.mp4` | 单个场景的高清版 | 1920×1080、30fps、H.264 |
| `out/<KEY>.mp4` | 总片：片头 + 各场景（按 `film` 截取）+ 片尾，评审会、周会里放 | 同上 |
| `out/<KEY>-15s.mp4` | 产品价值片：信息流/官网首屏 | 1920×1080、30fps、无声母版 |
| `out/<KEY>-30s.mp4` | 产品价值片：官网/发布会预热 | 同上，默认主版本 |
| `out/<KEY>-45s.mp4` | 产品价值片：需要解释机制时 | 同上 |
| `out/voiceover.md` | 后续接 TTS/配音的旁白与时间点 | 先留空或写草稿，不阻塞画面 |
| 配文 | 每张动图配一行 | 回复里给出，见 angles.md；已有本期卡片（`docs/releases/*.card.txt`）就配在对应条目下 |

产品价值片先交付**无音轨母版**；后续接声音合成时，画面时长和 beat 不变，单独输出配音版。不要在画面里烧录字幕，字幕/旁白单独维护。

群聊对动图的尺寸、体积上限各家不同，5MB 是保守值；第一次往某个群发时让用户实测一次，再把结论写回本节。

- 一份物料一个目录 `docs/promo/<需求 KEY>/`：`scenes.js` 入库；`out/`（产物）不入库。也可以自己写 `index.html`，
  用 `promo/kit.js` 的 `openApp()` / `setup()` 从头画（`docs/promo/auto-eval-evidence/` 是这种写法的早期样张）。
- 需要配置的原型开发服务器在跑（舞台页由 dev 服务伺服，和原型同源）；改了 `server/promo-server.js` 或 `vite.mjs` 要重启 dev。
- 渲染：场景之间并行（`--jobs`，默认最多 4 个浏览器），截图直接写进 ffmpeg 的标准输入、GIF 由 gifski 直接读成片，不落盘帧序列；
  日志按场景报「准备 / 逐帧 / 出 GIF」各花多久。哪一秒卡住超过 45 秒会直接报错，`PROMO_DEBUG=1` 重跑看停在哪条输入。
- 原型地址带 `promo`：正式环境快照、本机素材一律不加载，合成的演示素材照常加载（生成方式由宿主提供）。
  带 `clock`：注入虚拟时钟，原型那一侧的 localStorage / sessionStorage 换成内存里的一份——场景里「另存为」这类写操作不会污染你本地的原型数据。
- 源码改了之后：`builderharness promo status` 列出哪份物料要重渲。
- 要和**不在本仓库的页面**对比（线上平台、旧平台）时才拍静态截图：`promo.config.mjs` 写 `textures`，跑 `promo.mjs capture`。
- 发出去之前照常确认密级与范围：画面里只能有合成数据；内部链接只放在配文里，不烧进画面。

安装后运行 `builderharness promo doctor` 检查浏览器和编码器，再用 `builderharness promo init <KEY> --template scene|product-film` 创建配方。对外页面纹理采集用 `builderharness promo capture docs/promo/<KEY> --allow-external` 显式开启。

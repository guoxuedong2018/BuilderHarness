# Decision Log

跨需求、长期有效的决定记在这里。只记会影响后续实现或评审的判断，不记流水账。

## 如何更新

- 一个决定一条，日期 + 标题。
- 写清楚**背景**、**决定**、**代价 / 后续动作**。
- 需求局部决定留在该需求的 `README.md`；只有跨需求才进本文件。
- 改变了旧决定时，在新条目里链接旧条目，不删除旧记录。

## 记录模板

### YYYY-MM-DD · 决策标题

**背景**：为什么现在必须定。

**决定**：选了什么，不选什么。

**适用前提 / 范围**：什么条件下成立，哪些场景不适用。

**替代方案与代价**：考虑过哪些路径，各有什么成本和后果。

**证据 / 验证**：引用原文、实现、测试及其结果与局限；未运行明确写未运行。

**重新评估条件**：目标、约束或哪些证据变化后需要重评。

**替代关系 / 确认状态**：链接被替代的决定；明确用户已确认的内容，Agent 建议与假设不得标为已确认。

**后续动作**：会影响哪些页面、文档、适配器或流程。

### 2026-11-03 · PRD 规格只写前端看不到的逻辑，一条一句，写成规则体

**背景**：原型源码整份交给研发，PRD 再复述布局、列、界面文案，同一件事写了两份；规则写成口语和来龙去脉，研发读不出要实现的约束，还混进从原型和 mock 推出来、没人定过的规则。

**决定**：`spec` 只写前端看不到的逻辑——数据来源与范围、枚举与默认值、计算口径、状态与流转、校验与约束、保存与版本、对下游的影响、权限、外部调用；由数据决定的显示只写条件。判据：只拿到页面源码、没有 mock 的研发能不能知道这件事。每条一句、能单独验收，列举用「：」总起加子条（最多三级）；句式为「对象 + 条件 + 结果（+ 作用范围）」，不解释原因、不举例；没人定过的规则不写。发布前每条过四问（不看也不会做错？口语 / 原因 / 复述界面？别处写过？没人定过？）。功能点来源分四类，`online-page-new` 单独标出已有页面上新加的块。

**适用前提 / 范围**：所有写 `spec` 的需求件套。README 决策表、FLOW、acceptance 不受影响；界面文案仍按设计哲学第 8 条「说用户的话」。

**替代方案与代价**：把规则拆成卡片钉到原型元素上——研发按页面和接口开发，不按元素，太分散；做成自动检查（口语词清单）——误报多，漏的恰是读着通顺、其实没有依据的那种，所以四问留给判断。

**证据 / 验证**：上游工具箱在一份真实需求上按此精简，规则条数与字数都降到原来的四成左右，评审不再反馈「看不懂」「太啰嗦」。本仓库未在真实需求上复现。

**重新评估条件**：交付物不再包含原型源码，或研发改为按元素而不是按页面 / 接口开发。

**替代关系 / 确认状态**：上游由用户确认后迁入（用户决定通用能力都移植到 BuilderHarness）；示例改用示例原型的场景。

**后续动作**：`.agent/skills/prd-author`、`.agent/skills/prd-publish`（含 scaffold 副本）、`docs/templates/FRS.json`、`pipeline/export-frs-prd.mjs`。

### 2026-11-03 · 已发布 PRD 里人的改动：逐条列出、一直受保护，人删掉的不加回；大改先出修订稿

**背景**：PRD 评审期间有人直接在已发布文档里改。补丁只保护「对不上底稿」的段落，看不出改在哪个功能点下；人删掉的段落还会按 FRS 加回；一次改几百条直接落成定稿，人没法逐条核对。

**决定**：
- 出计划时把人的每处改动写进 `docs/prd/<KEY>/cloud-edits.md`（位置、层级、原文与现文、FRS 有没有）；补丁不动人改的、不加回人删的；人确认（已同步或不要）后才 `--absorb` 换底稿。
- 发布后的底稿只记「我们留下的段落」（`nextBase`）：人改过的记原文、人删掉的留着、人加的不记，保护一直持续到 `--absorb`；改写要写进去的若是人删掉的话，按删除处理，不借邻居段落加回。
- `--redline` 出修订稿：原文划线标红留原位，改写按相似度配对紧跟其后、浅绿底；重跑不重复；不带 `--redline` 再发一次即定稿（删划线、去底色）。删除线算进段落文本，人去掉删除线就是要保留，照常列进清单。
- 补丁每批最多 50 个操作，相邻删除合并，每批先试跑；中途失败留在文末的临时图下次自动删。

**适用前提 / 范围**：已发布、有底稿的 PRD 更新。需求背景与方案设计仍只提醒、不比对。小改直接发定稿。

**替代方案与代价**：自动把目标端改动写回 FRS——人的改动可能和本轮决定冲突，要人判断；用目标端的建议 / 评论模式——发布适配器不一定支持，评论塞不下完整改写；发布后直接拿目标端现状当底稿（上游原做法）——人的改动在下一次发布时就被当成「我们发的」覆盖掉，`--absorb` 失去意义。

**证据 / 验证**：`scripts/test-prd-patch-ops.mjs`（修订稿 → 重跑 → 定稿、去掉删除线算保留、跨两次发布仍受保护、不加回人删的段落、逐格对齐、分批）与 `scripts/test-prd-publish-flow.mjs`（假适配器上端到端：首发 → 人改 → 计划出清单 → 修订稿 → 重跑 → 定稿 → `--absorb`；临时图清理）。端到端测试先暴露了「保护只撑一轮」和「改写借邻居加回」两个问题，修复后通过。未连真实发布目标验证。

**重新评估条件**：发布目标原生支持修订 / 建议模式，或段落 id 能稳定追溯到 FRS 规则。

**替代关系 / 确认状态**：清单、`--absorb`、修订稿、分批上游已由用户确认后迁入；`nextBase` 与「改写不借邻居加回」是本次移植时发现问题后的修复，Agent 建议，待用户确认。

**后续动作**：`pipeline/prd.mjs`、`pipeline/prd-patch-ops.mjs`、`pipeline/destinations/docs-cli.mjs`（`folderId`）、`docs/publishing*.md`、`.agent/skills/prd-publish`；上游工具箱有同样的两个问题，改为依赖本仓库时一并带回。

### 2026-11-03 · 「用了却没引入」检查借宿主的解析器，借不到时明确降级

**背景**：只做语法检查时，漏一个 import 照样通过；到浏览器里才 ReferenceError，生产构建里整页白屏。React 宿主的 `.jsx` 原先完全不在检查范围内。

**决定**：`check-prototype-syntax` 按 ES 模块作用域找「用了却没声明、也没 import」的标识符，JSX 组件名算引用，并提示哪个文件导出了它；`typeof` 探测、`process.env.NODE_ENV`、`/* global */` 声明不算。解析器沿宿主依赖链借（宿主自己 → Vue SFC 编译器 → React 插件背后的 Babel），套件不装；借不到时 `.js` / `.vue` 照做语法检查，这一项与 `.jsx` 标「⚠ 降级」并列出没查的文件，不当成通过。TypeScript 文件列出、不检查。

**适用前提 / 范围**：原型工程 `src/` 下的 JS、JSX、Vue 2.7 脚本。

**替代方案与代价**：套件自带解析器——破坏「基础命令行零运行依赖」；借不到就跳过——静默通过，正是要防的误报；把 TS 也纳入——类型引用会产生大量误报，交给 tsc 与构建。

**证据 / 验证**：`scripts/test-check-prototype-syntax.mjs`（漏引入的组件和函数、补上后通过、无解析器时降级、JSX 语法错误带位置）；示例原型从只查 `.js` 变为查 16 个脚本、0 处问题。

**重新评估条件**：宿主普遍改用 TypeScript，或套件允许可选依赖。

**替代关系 / 确认状态**：检查本身上游已由用户确认后迁入；JSX 支持、依赖链顺序与降级方式是本次的抽象取舍，Agent 建议，待用户确认。

**后续动作**：`pipeline/lib/undeclared.mjs`、`pipeline/check-prototype-syntax.mjs`、`.agent/skills/frontend-quality`。

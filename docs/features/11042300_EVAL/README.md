# 用宿主项目自己的任务评测 agent harness

> 状态：运行器已实现，合成夹具自测通过；真实宿主试跑待进行，详见 [验收记录](./ACCEPTANCE.md)
> 创建日期：2026-11-04（Asia/Shanghai）
> Feature Key：11042300_EVAL
> 分级：M — 新增一个 CLI 命令与评测数据格式，不改变现有命令。

## 背景

CLAUDE.md、技能、hook、模型与推理强度都会影响 agent 的结果，但改动之后是变好还是变坏，宿主项目目前只能凭感觉判断。参考“从执行轨迹改进 harness”的做法：模型不变，只改提示、工具与中间件，用一组能重复打分的任务衡量每次改动。前提是有任务集和运行器。

运行器是通用能力，放在本仓库；任务、缺陷补丁、隐藏用例与轨迹属于宿主项目，含有宿主的代码，不进入本仓库。

## 范围

- `builderharness eval validate / run / compare / list`，零运行时依赖。
- 任务格式：`evals/suite.json`、`evals/tasks/<id>/`、`evals/variants/<name>/`，见 [docs/evals.md](../../evals.md)。
- 宿主：Claude Code 的 print 模式（stream-json 轨迹）；`command` 宿主用于自测，也可以包装别的 agent。
- 不做：云端存储、CI 运行、模型排名、自动合并评测里产出的修复。

## 设计要点

| 问题 | 做法 |
| --- | --- |
| agent 不能看到注入了什么 | 每次运行从基线提交导出快照，打补丁后 `git init` 成只有一个提交的新仓库 |
| 任务本身可能不成立 | `validate` 不调用模型：注入后目标项必须失败、其余项必须通过；撤回注入后全部通过；`run` 拒绝没有通过当前校验的任务 |
| 宿主自己的规则或设置混进评测 | 只加载项目级设置；工作目录必须在宿主项目之外，且上层目录没有 agent 指令文件；清除外层会话的 `CLAUDE*` 环境变量 |
| 只看结果看不到过程问题 | 从轨迹提取完成前验证、虚报、原地打转、越界改动与被拒命令 |
| 花费不可控 | 每次尝试 `--max-budget-usd` 封顶；`--max-total-usd` 控制整次运行；重复轮次交错执行，提前停止也覆盖每道题 |
| agent 留下的后台进程影响评分 | 每个步骤在独立进程组运行，结束时整组停止；评分前服务地址已被占用就报基础设施错误，不评分 |
| 轨迹含宿主代码 | 结果只写宿主本地被忽略的 `.builderharness/evals/`，不在 `.gitignore` 里时给出警告 |

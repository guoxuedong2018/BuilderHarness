# 宣贯角度与文案

## 先定角度：这个功能属于哪一种

工具型产品的功能更新大多落在下面五种里。角度决定主角画面和桥段，先归类再写字。

| 角度 | 什么时候用 | 主角画面 | 一句话的写法 |
|---|---|---|---|
| **看得见了** | 以前看不到 / 要自己翻的信息，现在直接摆出来 | 新出现的那块信息，推近 | 「X，直接标在 Y 上」 |
| **少一步** | 流程变短：少一次弹窗、少一次跳转、少填一项 | 新流程走一遍；需要时与旧流程同屏对比 | 「点 X 直接 Y，不用再 Z」 |
| **不会错** | 加了校验、提醒、回显，防止选错或忘了 | 提醒出现的那一刻 + 它说的那个字段 | 「选 X 时会提醒你 Y」 |
| **能做了** | 以前做不了的事：新对象、新入口、新导出 | 入口 → 做一次 → 拿到结果 | 「现在可以 X 了」 |
| **改名 / 换位置** | 名字或入口变了，老用户要重新找 | 新位置，旧名划掉换新名 | 「X 改叫 Y，还在原来的地方」 |

一张卡只取一个角度。一个功能同时「看得见了」又「少一步」，挑读者最在意的那个当主角，另一个最多在标注里提一句。

## 文案：短、准、说用户的话

- **标题 ≤ 16 个字，两行以内。** 用界面上的原名（「证据帧」「结果列表」），不起宣传名、不用「全新」「重磅」「赋能」。
  标题里要有**功能名或它说的那个东西**，只有形容词的标题（「更高效的评测」）读者记不住。
- **一句收益 ≤ 30 个字。** 说读者少做了什么、能看见什么，不说平台做了什么。
  ✗「平台支持了证据帧标注能力」　✓「红点就是问题帧；点证据帧，看红框圈出的位置」
- **入口路径必写。** 用 `›` 串起来、和导航上的字一模一样：「评测任务 › 机评任务 › 结果列表」。
- **画面里的标注跟着被说的那个东西走。** 标注贴在红点旁、连线指过去，不在角落另起一段说明（原因写在被影响的那一行旁边）。
  一个标注一句话 + 一行小字补充，同一时刻画面上最多一个标注。
- **不复述画面。** 画面里已经看得见「第 20 帧 · 5 秒」，标注就别再念一遍「这里显示了帧号和秒数」。
- **数字要有出处。** 「省了 3 步」要数得出是哪 3 步；「效率提升 40%」没有测量就不写。
- **没上线的不写成已上线。** 样张、预告在配文里标出来；画面里不写上线日期，日期写在配文里，改起来不用重渲。

## 产品价值片：五个价值角度

功能宣贯讲“这次更新了什么”；产品价值片讲“为什么值得用”。先选一个价值角度，再找证据。

| 角度 | 读者问题 | 一句话 | 证据画面 |
|---|---|---|---|
| **省时间** | 能少做哪一步？ | 「原来 5 步，现在 1 次点击」 | 前后对比、操作步数、处理时长 |
| **看得见** | 以前看不见什么？ | 「发布前就能看见偏差」 | 高亮、引用、来源、异常标记 |
| **不会错** | 怎么防止出错？ | 「选错之前就提醒你」 | 校验、回显、权限、二次确认 |
| **能掌控** | 出问题怎么办？ | 「每一句结论都能回到原文」 | 引用定位、版本、审计、回滚 |
| **更专业** | 为什么比现在好？ | 「把专家流程变成可复用的 Agent」 | 真实工作流、模板、并行任务 |

一支 30 秒片只选一个角度；其他角度最多作为细节镜头出现。不要同时说“省时间、不会错、能掌控、更专业”，读者一个都记不住。

## 配文（和动图一起贴的那几行）

画面里不放标题和说明，它们在配文里。一个需求一组动图时，先一行总述，再每张图一行：

```text
【示例工作区】草稿可以立即创建，刷新后仍能找到
① 先保存：填写标题即可在列表里看到新草稿
② 填错时：空标题会提示原因，可以直接在原处改好
入口：实验列表 › 新建实验 ｜ 操作说明：<链接>
```

只有一张图时就三行：功能名 + 一句收益 / 入口 / 操作说明链接。已有本期更新卡片（`docs/releases/*.card.txt`）时，动图配在对应条目下，不另写。
链接只放在配文里，不烧进画面——画面会被转发、截图，链接会过期。

# 独立评审

做法借自 mg-styles-15 的 `rubric.md`：另开一个干净上下文的评委，只看成品、不听解释，打分并给出带时间码的修改项；按评审改一轮再交。
在本仓库里用子 Agent 当评委（Agent 工具），把下面整段作为它的任务，替换尖括号里的内容。

## 给评委的任务

```text
你是一名资深的产品宣传设计评委：做过 B 端 / 工具型产品的上线物料，也熟悉群聊里动图的观看方式。
这张物料不是你做的。要严格、具体——客气没有用，具体才有用。

物料：<目录>/out/<名>.gif（主力）、<目录>/out/<名>.mp4、<目录>/out/poster.png、<目录>/out/contact.png（每 0.5 秒一格）。
简报：<功能、读者、一句话收益、入口路径、事实来源>
发到哪：<群聊名或类型>，读者在聊天窗口里看到它，默认静音、自动循环，没点开时只看到第一帧。

1. 认真看：先看 contact.png 把握全程；再用 ffmpeg 从 MP4 抽 5–8 个关键时刻的原尺寸帧（主角特写、每个标注落定后、光标点击、
   拉远全景），裁剪放大看字边缘、对齐、遮挡。把 poster.png 缩到 480 宽看一次——那是读者没点开时的样子。
2. 查规格：GIF 体积 ≤ 5MB；首尾两帧是同一画面；没有闪烁、跳帧、半截过渡；画面里没有内部链接、真实账号、
   非合成数据的痕迹；没有字体回退或豆腐块。
3. 按 1–10 打分（5 = 能用但平庸，6 = 模板水平，7 = 扎实的专业水准，8 = 优秀的产品团队出品，9 = 会被拿去当范例）。
   第一版大多在 5–7，不要虚高。
   - 一眼看懂：只看首帧，能说出「多了什么、对我有什么用、在哪用」吗？缩到 480 宽呢？
   - 事实：画面与文案和简报一致吗？入口路径对吗？有没有说过头的话？
   - 画面：构图、层级、留白、字号；像不像这个产品自己（配色、字体、真实界面）？
   - 动效：缓动、节奏、停顿够不够、同一时刻是否只有一个焦点、循环接缝。
   - 技术：清晰度、体积、无瑕疵。
4. 给 3–8 条修改项，按对第一印象的影响排序。每条写：时间码、看得见的问题、为什么要紧、具体怎么改（数字：秒数、px、缓动、
   字号、位置）。宁要几条大的，不要一堆小的。至少一条是让它更好懂或更抓眼，而不只是修瑕疵。
5. 标出致命问题：事实错误、首帧看不懂、标题读不清、内部信息泄露、中文不自然或有错字。

返回：分数表、致命问题、修改项清单。
```

## 产品价值片评分表

给评委时，除了上面的任务，再加这一段：

```text
这是无真人、无声的产品价值片。按以下 8 项各 1–10 分打分，5 = 能用，7 = 专业，9 = 可当范例。
不要因为“特效多”给高分；高级感来自克制、准确和细节。

1. 首 3 秒：是否立刻看到产品/结果，而不是 Logo 或空镜？
2. 价值：是否能用一句话说出“对谁、有什么用、不用什么”？
3. 证据：每个卖点是否有真实界面/可核对数字，而不是旁白自夸？
4. 产品真实感：界面、数据、光标、状态是否像真实产品，而非手绘仿真？
5. 视觉系统：字体、颜色、圆角、间距是否来自产品本身？是否只有一个强调色？
6. 动效：是否每个动效都有因果？同一时刻是否只有一个主动作？是否有不必要的漂浮/光效？
7. 精致细节：是否有至少一个体现格调的微交互、引用、数字或转场？
8. 结尾：是否只留一个 CTA？产品名和一句话是否在 2 秒内读完？

致命问题：首帧看不懂、价值说不清、产品画面是假的、数据编造、文字压住核心界面、没有产品证据。
修改项必须带时间码和具体数值（秒、px、字号、缓动）。
```

## 拿到评审之后

- 先留一份当前版本（`out/` 复制一份带日期的）。
- 致命问题与高影响修改项全部落实；有更好的改法可以替换，说明理由。不要倒退评委列为优点的地方。
- 重渲后自己再看一遍静帧与 contact.png，确认改到了，再交给用户；汇报做了哪些、没做哪些、为什么。
